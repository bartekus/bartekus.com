# Agentic code collapse, and the substrate that prevents it

*Update, July 2026: the codebase these receipts come from, open-agentic-platform, has since been rebuilt ground-up as [Statecraft](https://github.com/statecrafting/statecraft) under the same spec-spine substrate; the rewrite itself is the strongest evidence yet for the argument below. [From Open Agentic Platform to Statecraft](/writing/from-open-agentic-platform-to-statecraft) tells the rename story.*

There is a failure mode stalking every team that has handed serious codebase work to AI agents, and it does not have a settled name yet. I call it **agentic code collapse**: the point at which an agent-built system has accumulated so much locally-plausible, globally-incoherent change that both humans and agents lose the ability to extend it. Velocity does not decline gracefully; it inverts. Every new feature spends most of its budget rediscovering what the system already is.

I run a codebase that should, by every prior, have collapsed already. It has not, and I can show mechanically why. But first, the disease.

## The anatomy of collapse

Collapse is not one bad merge. It is compound interest on small incoherences, and it follows a recognizable progression:

1. **Duplication creeps in.** An agent that cannot find the existing helper writes a second one. Both pass review, because each is fine in isolation. Now there are two, and the next agent finds the wrong one first.
2. **Orphans accumulate.** Modules whose purpose nobody can state, crates wired to nothing, code whose owning intent left no forwarding address. Deleting them feels risky precisely because nobody can say what they are for.
3. **The documentation lies.** READMEs describe the architecture of three refactors ago. The cost of stale docs in an agentic codebase is worse than in a human one, because agents *believe* documentation with great sincerity and act on it at machine speed.
4. **Architecture becomes oral tradition, with no speakers.** In a human team, tribal memory degrades when people leave. Agent sessions "leave" every few hours. Each new session re-derives the system's shape from scratch, slightly differently, and writes code consistent with its own derivation rather than with the system.
5. **The codebase turns hostile to its own maintainers.** Human or agent, anyone making a change can no longer predict its blast radius. Work slows, confidence drops, and the rational move becomes rewriting subsystems rather than understanding them, which accelerates the spiral.

The root cause is not model quality. It is that generation became free while coherence stayed expensive. An agent can produce code faster than anyone can integrate its *meaning*, and meaning is the thing collapse destroys: not whether the code runs, but why it exists, what owns it, and what may touch it.

## The counterexample, with receipts

The codebase behind [open-agentic-platform](https://github.com/bartekus) is the most agent-generated thing I have ever worked on, and by the logic above it should be a ruin. The current footprint, straight from `cloc`:

| Language | Files | Lines of code |
|----------|-------|---------------|
| TypeScript | 886 | 147,069 |
| Rust | 402 | 98,875 |
| JavaScript | 34 | 17,375 |
| Python | 40 | 4,841 |
| Go | 12 | 104 |
| **Total** | **1,374** | **268,264** |

That is 268 thousand lines across six hundred directories: eighteen Rust crates, twenty-two npm packages, eleven CLI tools, a Tauri desktop app, two platform services, Terraform, Helm charts, and a GitOps tree. Built in four months by one human directing agents, under a hundred and forty-eight specifications (numbered 000 through 147) that govern all of it.

The interesting claim is not the size. It is that the coherence properties collapse destroys are still intact, and *provably* so rather than anecdotally:

- **Nothing is unowned.** Every crate and package declares its owning spec in its own manifest; a compiled index maps every governed path back to the specs with authority over it. "What is this crate" is answered by following its manifest to a spec, not by asking around.
- **Orphans are a query, not a vibe.** The compiled index knows every governed path and every claiming spec, so code whose owning intent has gone missing is a list you can print, which means it is a list you can drive to zero.
- **The docs cannot drift, because the load-bearing ones are compiled.** There are deliberately no per-crate READMEs; prose lives in the owning spec, and the inventory document is regenerated from the manifests themselves. The repo treats hand-maintained duplicate truth as a defect class and removed it.
- **Duplication has an immune response.** A spec must declare the territory it establishes, extends, or refines, and a coupling gate refuses merges where code and declared territory disagree. A second copy of an existing capability has nowhere legitimate to live: claim the territory and collide with its owner in the graph, or claim nothing and fail the gate.
- **The corpus deletes things.** This is the discipline I am proudest of. Consolidation specs exist whose whole purpose is demolition: one absorbed five separate crates into a single agent crate and deleted the originals; another deleted an entire top-level subsystem tree and moved its state into the platform's database. Out of a hundred and forty-eight specs, four have been superseded and none merely abandoned; direction changes are recorded as supersession, with the successor named, so even the failures have forwarding addresses.

## Why the substrate is the cure

Map the failure progression onto mechanisms and the pattern is exact; every stage of collapse is an entropy leak, and each leak has a specific gate sealing it.

Sessions are amnesiac, so **intent must be durable somewhere outside the session**. That is the spec corpus: every feature's reasoning survives as a typed markdown artifact, and a fresh agent re-derives nothing; it queries the registry for what the system is and what it owns.

Each diff is locally plausible, so **coherence must be checked globally and mechanically**. That is the [coupling gate](/writing/architecting-intent-vs-vibe-coding): every PR is cross-referenced against the authority graph, and drift between intent and implementation is a failed merge, not a smell.

Generated artifacts go stale silently, so **staleness must be detectable without re-analysis**. The compiled registry and index are deterministic, content-hashed, and committed; a one-command check compares hashes and fails CI when any governed input changed without the index following: manifests, specs, schemas, workflow definitions, and the agent rules themselves.

And agents under pressure will try to edit the contract to match their code, so **the contract needs a prompt-time defense too**: a standing refusal rule that obliges an agent to halt and surface the contradiction rather than amend a spec to escape a failing gate. The gate seals the merge-time leak; the refusal rule seals the one upstream of it.

None of these mechanisms is clever in isolation. The property that matters is that together they convert entropy into *visible, blocking failure*. Collapse feeds on silent divergence; here, divergence has nowhere silent to happen.

## What it costs

Honesty requires the bill. The gates have friction: regenerating the index belongs in the same commit as the change that staled it; golden test files must be regenerated when the spec corpus moves; two branches that both regenerate the index will conflict on it, and one of them pays a regeneration cycle; and a coupling gate will occasionally block a PR you believe is innocent until you either fix the ownership declaration or write an explicit, recorded waiver. I pay minutes of friction per change, routinely.

But that is the trade stated plainly: minutes of mechanical friction, continuously, against the compounding loss of the system's intelligibility. Collapse does not send an invoice until the balance is unpayable. The spine bills you per commit, in amounts you can always afford.

## The thing better models will not fix

The tempting belief is that collapse is a model-quality problem that the next generation will solve: smarter agents, longer context, better memory. I do not believe it, and the reason is structural. Collapse is not caused by agents writing bad code; it is caused by *nothing in the system being responsible for coherence between intents*. A brilliant agent with a million-token context still cannot know that a path is owned, that a duplicate exists, or that a spec staged a future decision, unless something durable and queryable says so. Coherence is not an emergent property of intelligence. It is a property of substrate.

That substrate is what I intend to lift out of this codebase and release standalone: the compiler, the registries, the gate, the refusal rule, the grammar, Apache-2.0, adoptable by any repo. Not because my codebase is special, but because the failure mode is universal and the cure should be portable.

Agentic code collapse is real, it is already eating codebases, and it is optional. You do not prevent it by reviewing harder or prompting better. You prevent it by making incoherence impossible to merge.

An update from June 2026: the extraction shipped. The substrate is now a standalone tool, [spec-spine](https://github.com/bartekus/spec-spine), and the full write-up of its model is in [Inside spec-spine](/writing/inside-spec-spine).
